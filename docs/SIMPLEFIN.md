# SimpleFIN bank-sync trial

Open the header data menu → **Bank sync · trial**. Use the existing cloud-backup sign-in. Check bank support at https://beta-bridge.simplefin.org/search-institutions before buying a subscription. For a small trial, choose monthly billing in SimpleFIN and connect one active bank. Create an app setup token named BonusTracker at https://bridge.simplefin.org/simplefin/create and paste it only into the app's setup field. All discovered accounts enter read-only transaction monitoring automatically; linking a checking/savings account to a bank-bonus cycle remains optional and must identify the exact eligible open cycle.

The backend exchanges the single-use setup token over HTTPS, encrypts the Access URL and saved evidence with a separate server key, and stores it in an owner-scoped R2 prefix outside backups and screenshots. No bank token or transaction evidence is saved in browser storage, ordinary tracker exports, or AI requests. Existing signed owner verification applies to every route. Provider redirects, arbitrary hosts and custom ports are rejected.

Discovered accounts synchronize automatically at most every six hours while the backend is running. Manual refresh is limited to once every two hours, and SimpleFIN's published guidance permits only limited daily retrievals; a faster application poll does not guarantee fresher bank transactions. The initial transaction fetch starts after linking when provider capacity permits; connecting another institution during an existing daily window may delay new transactions until the next eligible check. The scheduler resumes after a restart; missed offline changes are not represented as current. The bounded 90-day provider retrieval window catches delayed records. Provider IDs are scoped by connection, account, and transaction. Pending rows are displayed as pending but excluded from posted totals; missing pending rows are cleared only after a complete provider retrieval. Missing rows do not prove reversal, closure, completed requirements or nonpayment. Changed rows are identified; explicitly described reversal debits are review candidates. The first trial shows activity and possible promotional credits, and **does not mark tracker milestones or bonuses paid automatically**. It does not certify direct-deposit qualification or continuous balance maintenance.

Already-observed transaction history is retained in owner-private encrypted monthly shards with a verified conditional-write root manifest; no previously discarded observations can be recreated. Each shard is limited to 200 rows. Newly discovered accounts monitor by default unless expressly excluded. account-list discovery retains basic account labels and balance snapshots. The user may pause transaction monitoring per account or remove one account from Finances without disconnecting the entire provider. Bonus matches must still be selected explicitly and never create a confirmed tracker milestone. Changing a mapped cycle clears its previous trial evidence. A missing or replaced tracker cycle is not presented as evidence for a new cycle. Warnings and incomplete responses stay visible. Retrieval time, source balance date and unknown transaction completeness are distinguished.

Disconnect removes the whole SimpleFIN Bridge connection's locally stored credential and sync data by writing a disconnected tombstone. It does not close bank accounts, revoke the upstream SimpleFIN token or cancel the SimpleFIN subscription; manage those in SimpleFIN.

Backend deployment requires a stable `SIMPLEFIN_ENCRYPTION_KEY` (Fernet key). Never rotate it casually: existing encrypted state would become unreadable. There is no database migration, new paid hosting service, or extra bank-provider account activated by deploying this feature. No automatic paid upgrade exists.

Verification: backend unit/route tests cover encryption, owner isolation, URL restrictions, duplicate/pending handling, corrections, retention, rate limits, credential persistence and disconnect. `tests/bank-sync.e2e.cjs` exercises phone widths in Chromium, Firefox and WebKit with synthetic bank data; no live account is used by tests. Live coverage and refresh reliability remain unverified until an authorized account trial.

## Plaid Trial fallback (2026-10 automatic sync)

SimpleFIN remains the primary provider. Plaid is an optional fallback for institutions SimpleFIN cannot connect. A successful Plaid authorization creates a permanent lifetime Trial Item; the global ten-Item allowance **never increases again** when an Item is disconnected. The app automatically discovers authorized Plaid accounts and imports eligible transactions in the next permitted sync (three-hour scheduled window; 30-minute manual cooldown). Plaid backfill is bounded and provider data may be incomplete or delayed.

Finances → Accounts exposes a direct, per-bank **Remove bank** control for Plaid. The confirmed removal invokes Plaid Item revocation, purges saved data for that Item, and preserves bank-bonus tracker records. The SimpleFIN disconnect removes all Bridge-connected institutions and requires separate provider-side token revocation. Neither operation closes an actual bank account, confirms a bank bonus, or makes transfers.

## Managing a single bank account

Finance → Accounts → expand the specific account → **Remove this account**. Confirm to remove its active financial history and keep its other institution accounts linked, even if both use a single SimpleFIN Bridge or Plaid Item. This does not close an actual bank account, remove a Plaid Trial Item, or modify a bank-bonus tracker entry. An account-key exclusion prevents automatic rediscovery; **Removed accounts → Restore** allows discovery again without re-linking Robinhood. Pausing monitoring keeps the account card but stops retaining its transactions. Encrypted superseded shards can persist transiently pending cleanup.
